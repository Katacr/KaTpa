# 传送请求

## 两种传送方向

| 指令 | 结果 | 示例 |
| --- | --- | --- |
| `/tpa [玩家]` | 你传送到对方的位置 | `/tpa Steve` |
| `/tpahere [玩家]` | 邀请对方传送到你的位置 | `/tpahere Alex` |

省略玩家名时会打开在线玩家选择菜单。跨服功能启用后，列表也会包含其他子服务器的在线玩家。

## 接受或拒绝

接收方可以使用界面按钮，也可以输入：

```text
/tpaccept
/tpdeny
```

`/tpaaccept` 是 `/tpaccept` 的兼容别名，`/tpadeny` 是 `/tpdeny` 的兼容别名。

当你同时收到多条请求时，执行接受或拒绝指令会打开待处理列表。列表中的每条请求都有独立的同意和拒绝按钮，不会误处理其他玩家的请求。

## 撤销请求

发送成功提示末尾提供 `[撤销]`。也可以输入：

```text
/tpacancel
```

每名玩家同一时间只能发出一条待处理请求。撤销请求不会返还已经开始的请求冷却。

## 请求超时

请求必须在服主设定的时间内处理。待处理列表会显示剩余时间；最后一条请求被处理或超时后，列表会自动关闭。

## 传送倒计时

请求被接受后，需要传送的玩家会进入准备时间：

* ActionBar 显示剩余秒数
* 每秒播放倒计时音效
* 玩家身边出现末影风格粒子
* 实际改变位置会中断传送，原地转动视角不会
* 受到有效伤害或相关玩家离线会中断传送

传送完成时会播放末影人传送音效。

## 无法发送请求的常见情况

* 请求仍在冷却中
* 你已经发出一条尚未处理的请求
* 需要传送的玩家正在进行另一场传送
* 当前世界被服主禁用
* 服务器禁止跨世界传送
* 对方将你加入了黑名单

## 跨服与副本世界

当目标玩家所在世界被目标服的 `modules.tpa.disabled-worlds` 禁止时（例如对方正在副本中），**接受环节会在对方所在子服直接拒绝**，避免旅行者先被切服、却在落点阶段才失败而滞留在目标服。

- `/tpa`：目的地是接收者 → 接收者身处黑名单世界时无法接受，双方均收到提示。
- `/tpahere`：旅行者是接收者自己 → 接收者（即旅行者）身处黑名单世界时无法接受。

> 该检查在**目标服**配置生效（谁被传送进去，就看谁的服配置）。落点阶段仍保留一次兜底校验。
